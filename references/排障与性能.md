# 排障与性能

| 工具 / 出处 | 原始链接 | 用途 |
|---|---|---|
| strace | https://strace.io/ | syscall 序列、errno、阻塞点定位 |
| ltrace | https://ltrace.org/ | 库调用与动态链接行为 |
| perf | https://perf.wiki.kernel.org/ | CPU 采样、off-CPU、硬件事件、record/report |
| eBPF 上游 | https://ebpf.io/what-is-ebpf/ | 可观测与追踪能力总览 |
| bpftrace | https://github.com/bpftrace/bpftrace | 一次性探针语言，快速取证 |
| BCC 工具集 | https://github.com/iovisor/bcc | biolatency、opensnoop、offcputime 等 |
| SystemTap | https://sourceware.org/systemtap/ | 深度内核追踪与 stap 脚本 |
| Valgrind | https://valgrind.org/ | memcheck、helgrind、DRD、cachegrind |
| AddressSanitizer/UBSan | https://github.com/google/sanitizers | 编译期插桩的内存与 UB 检测 |
| gdb | https://sourceware.org/gdb/ | 崩溃现场、core 分析、线程回溯 |
| ftrace | https://docs.kernel.org/trace/ftrace.html | 内核侧函数追踪与延迟直方图 |
| proc(5) / procfs | https://man7.org/linux/man-pages/man5/proc.5.html | fd、maps、smaps、status 现场读取 |

## 取证顺序（固定）

1. 现象复现（最小用例 + 时间戳）；2. `strace -f -tt -e trace=...` 或 `perf trace`；
3. 资源面 `pidstat`/`vmstat`/`/proc/<pid>/fd`；4. CPU 面 `perf record -g`；
5. 内存面 ASan/valgrind；6. 内核面 bpftrace/ftrace；7. 根因 + 修复 + 回归验证命令。

无以上任一输出，不得写「已定位根因」，只能标「推测」。
