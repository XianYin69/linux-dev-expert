# 惩罚机制

## 规则

1. 同一失败（同一步骤、同一校验、同一归因签名）重试计数由
   `python scripts/penalty.py bump --sig <签名>` 维护。
2. 计数达 **10 次即熔断**：强制停止原做法，二选一——
   回退到上一稳定状态（`git reset --hard` 到该步骤起始提交，或 `process_chain.py interrupt`），
   或向用户求助并列出已试方案与失败输出。
3. 熔断后不得「换个说法再试一次」：必须先做根因分析（错误签名、已试次数、是否同类重复），
   分析入逻辑链，再决定修复路径或重试路径。
4. 同类错误重复出现视为需要修复，不是继续重试；无进展重试不增加成功概率，只消耗预算。
5. 计数清零条件：归因签名变化（确证为不同问题）或该步骤校验通过。
6. 计数与熔断记录存用户缓存目录（`~/.cache/linux-dev-expert/penalty.json`），不写技能目录。

## 降级顺序（熔断时按序尝试）

1. 缩小作用域（整步 → 单子项）；2. 换取证手段（man → 实测 → 上游文档）；
3. 换实现路径（systemd → 脚本 + supervisor）；4. 转派依赖技能；5. 求助用户。

## 违反后果

- 无限重试耗尽上下文与时间预算，且反复输出同一错误结论，损害可信度。
