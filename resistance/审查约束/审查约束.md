# 审查约束

整体审查（`branch/流程/整体审查/`）的九项标准与判据。任一项不过 → 记中断并回修。

## 九项标准

1. **结构完整**：`SKILL.md`、`agent/`（CLAUDE.md、agent_prompt.md、instructions.md、
   .cursorrules）、`asset/`（knowledge + checklists + knowledge_tree.json + asset.md）、
   `references/`、`dependence/`（dependence.md + deps.json）、`resistance/`、`branch/`、
   `planned_tasks/`、`scripts/`、`LICENSE`、`CHANGELOG.md`、`.gitignore` 齐备。
2. **frontmatter 合法**：`name`/`version`/`description`/`license: MIT`/`metadata.category:
   development` 齐全，`name` 与目录名一致。
3. **行数红线**：所有 `.md` ≤ 50 行（脚本 `.py` 不限行数，但禁裸 except、调试 print 残留、
   >100 字符长行、超长函数）。
4. **链接零悬空**：`python scripts/check_links.py` 报告悬空链接数为 0（相对路径逐条解析）。
5. **脚本真实存在**：SKILL.md 与 knowledge_tree.json 提到的每个脚本，相对技能根必须存在
   且带扩展名；`python scripts/run_tests.py` 全绿。
6. **依赖合规**：`python scripts/deps_check.py` 通过——字段齐全、`source_url` 非空、
   本地技能目录存在、无内嵌他技能正文。
7. **约束齐备**：`resistance/` 含探测优先、破坏性命令、root 权限、WSL 差异、薄技能依赖、
   git 工作流、五大机制、沙盒兜底；无删除约束记录。
8. **知识树不可再拓扑**：九叶互斥且并集覆盖 Linux 程序开发面，每叶有主问句、知识、清单、
   探针与出处；新增叶须过拓扑判据。
9. **git 历史合规**：`feature/*` → `dev` → `main` 合并记录完整，无直写 main/dev，
   `git status` 干净，无临时产物入库，无远端推送。

## 判据要求

- 每项结论附命令与输出摘要；未运行的不得写「已通过」。
- 正反双链辩论（`logic_chain.py debate`）记录在逻辑链中，裁决留痕。

## 违反后果

- 交付物不可加载或链接断裂；红线失守导致技能被整体退回。
