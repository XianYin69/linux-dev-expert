# 上下文压缩机制

## 规则

1. 单文件 ≤ 50 行是硬红线（markdown）；超限即拆叶或拆约束，不得靠缩小字号/挤行规避。
2. 知识只写「判据 + 坑位 + 取证命令」三段，不写教程叙述；叙述性内容指向
   [`references/`](../../references/references.md) 的出处，不复述原文。
3. 跨文件信息用链接传递，不用复制粘贴；同一事实只在一处维护（单一真源）。
4. 探测输出进上下文前先压缩：只保留判定所需字段（`ID`、`VERSION_ID`、`uname`、PID1、
   包管理器、编译器版本），其余丢弃或摘要为一行。
5. 长命令序列写成脚本入库（`scripts/`），上下文里只留调用行与结论，不贴整段输出。
6. `python scripts/context_compress.py` 用于估算与裁剪：超预算时按「红线 > 判据 > 示例」
   优先级丢弃，丢弃项须记入逻辑链以便复原。

## 降级

- 复原需要被丢弃的原文时，按逻辑链记录的出处重新取证，不得凭记忆补写。

## 违反后果

- 上下文膨胀导致后续步骤丢失红线约束，产生越权或口径漂移的决策。
