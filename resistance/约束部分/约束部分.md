# 约束部分（红线区识别）

## 什么算红线区

- 本目录 `resistance/` 全部文件；
- `SKILL.md` 的「红线」小节与 YAML frontmatter；
- `planned_tasks/` 的 schema 字段名；
- `dependence/deps.json` 的必填字段（`name`/`source_url`/`license`/`version`/`install`/`checked_at`）；
- `asset/knowledge_tree.json` 的叶 id 与 `knowledge`/`checklist`/`probes` 路径字段。

## 识别规则

1. 文本含「必须 / 禁止 / 不得 / 一律 / 默认拒绝」即判为约束语句，属红线区。
2. 约束语句的解释不得改写其强度：「默认拒绝」不得被解释为「确认后可执行」。
3. 红线区内容变更须走自更新接口（tmp 镜像 → compare → release），不得就地直写。
4. 红线区文件不得删除；确需退役，先在上层留下替代约束并记 CHANGELOG。

## 与知识区的分界

- `asset/knowledge/`、`asset/checklists/`、`references/` 属知识区：可增补、可修订，
  但结论强度（blocking / advisory）须与红线区一致，冲突时以红线区为准。
- 知识区条目未取证的须标 `[未取证]`；红线区不接受「未取证」豁免。

## 违反后果

- 约束强度被稀释后，破坏性操作与越权写盘可能被「合理化」，属不可撤回风险。
