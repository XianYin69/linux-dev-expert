# 修改流程

对既有 linux-dev-expert 做定向变更的独立路径：初始化 → 修改流程 → 完成。

## 节点

1. **定位影响面**：改动落在哪些叶/约束/脚本；用 `knowledge_index.py` 与 `check_links.py`
   找出引用方，列出将被影响的文件清单。
2. **tmp 镜像**：一切内容修改先在 `tmp/` 下按相对路径镜像，禁止直写技能目录。
3. **红线复核**：改动是否削弱既有约束（强度不得下降）；`resistance/` 文件不得删除。
4. **一致性**：`asset/knowledge_tree.json` 与 `references/知识树.md` 同步；
   新增/删除脚本同步 `scripts/scripts.md` 与 `SKILL.md` 的工具小节。
5. **依赖**：新增依赖同时写 `dependence/dependence.md` 与 `deps.json`（含 `source_url`），
   跑 `deps_check.py`。
6. **审查**：`run_tests.py` → `check_links.py` → `deps_check.py` → `garbage_collect.py audit`；
   失败记 `interrupt` 并回修。
7. **释放与提交**：`self_update.py compare` → `release --yes`；
   功能分支提交 → 审核通过合 `dev`；记 `CHANGELOG.md`。
8. **完成**：`process_chain.py finish --path modify`，标记「完成项目修改」并交回调度方。

## 判据

- 只改被要求的部分；顺手重构须先经用户确认并单独开功能分支。
- 修改后仍须满足 [`../../resistance/审查约束/审查约束.md`](../../../resistance/审查约束/审查约束.md) 九项。
