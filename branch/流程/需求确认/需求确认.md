# 需求确认

判定走创建还是修改，并把范围钉死；范围外的转派，不就地硬答。

## 节点

1. **路径判定**：目标目录不存在或为空 → 创建路径；已有技能 → 修改路径。判定结果入逻辑链。
2. **平台边界**：确认是 Linux 平台程序开发。Windows 桌面 → windows-app-dev-expert；
   Web 前端/界面设计 → interface-design-expert；纯语言语义 → c-expert/cpp-expert/python-expert。
3. **目标环境采集**：发行版族、内核、架构、init、包管理器、是否容器/WSL
   （`python scripts/probe_os.py --json`）。无目标机时记「未探测」并列出待验证命令。
4. **交付形态确认**：库/可执行/服务/容器镜像/包；决定后续走
   `elf-abi-dynamic-linking`、`systemd-dbus-cgroup-security` 还是 `distro-packaging`。
5. **约束确认**：是否允许 root、是否可装包、是否有网络、是否允许重启服务——
   逐项落到 [`破坏性命令约束`](../../../resistance/破坏性命令约束/破坏性命令约束.md) 与
   [`root权限约束`](../../../resistance/root权限约束/root权限约束.md)。
6. **验收标准**：与用户确认「什么输出算完成」，写入整体审查的判据。

## 出口

`process_chain.py step 需求确认`，提交 `feature/flow`。
