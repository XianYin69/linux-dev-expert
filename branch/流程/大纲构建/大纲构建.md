# 大纲构建

把取证结果组织成知识树拓扑与目录骨架，先定结构再填内容。

## 节点

1. **三段切分**：接口层（POSIX/glibc/系统调用）、运行时层（进程/线程/IO/内存序）、
   交付层（链接构建/服务化/打包/可观测）。
2. **定叶**：每叶给一个「主问句」，九叶互斥且并集覆盖 Linux 程序开发面
   （见 [`../../references/知识树.md`](../../../references/知识树.md)）。
3. **拓扑冻结判定**：再拆会与另两叶交叉即判「不可再拓扑」，写 `topology_frozen: true`。
4. **目录骨架**：`SKILL.md`、`agent/`、`asset/{knowledge,checklists}`、`references/`、
   `dependence/`、`resistance/`、`branch/`、`planned_tasks/`、`scripts/`。
5. **审阅**：逐叶检查是否有对应探针脚本与出处；缺任一项即回节点 2 合并或补叶。
6. **机读表**：`asset/knowledge_tree.json` 每叶记 `id/title/question/knowledge/
   checklist/probes/sources`。

## 判据

- 语言语义、界面设计、Windows 平台不入树 → 转派（[`../../dependence/dependence.md`](../../../dependence/dependence.md)）。
- 单叶知识 ≤ 50 行；超限即拆段或指向 references。

## 出口

`process_chain.py step 大纲构建`，提交 `feature/flow`。
